# Product Backlog — Automated Regulatory Monitoring and Compliance Management System

| User Story ID | User Story | Story Point | Priority |
|---|---|---|---|
| 1 | **As a** compliance officer, **I want** the system to automatically scrape regulatory updates from 5 international authorities (MAS, FATF, FinCEN, ECB, FCA), **so that** the compliance team receives the latest regulatory data without manual effort. **Given** the server is running, **when** the automated cron job triggers (every 14 days or on startup if DB is empty), **then** the Scraper agent visits regulatory websites, follows links to fetch full page content, skips PDFs/binary files, checks for duplicates by title, and inserts new regulations into MySQL. **Acceptance Criteria:** • The system shall scrape 5 regulatory sources via HTTP with Cheerio HTML parsing. • The scraper shall follow links on listing pages to fetch individual regulation page content. • The system shall skip PDF, DOC, XLS and other binary file URLs. • The system shall check content-type headers and reject non-HTML responses. • New regulations shall be stored with source_id, title, category, content (max 5000 chars), version, and source_url. • The scraper shall run on a 14-day node-cron schedule and auto-trigger on startup if regulations table is empty. | 5 | Must Have |
| 2 | **As a** compliance officer, **I want** the system to automatically detect changes when a regulation is updated to a new version, **so that** I am aware of regulatory modifications that may affect the bank's compliance posture. **Given** the scraper finds a regulation that already exists in the database with different content, **when** the content has changed, **then** the system stores both old and new content in regulation_changes and emits a regulation.updated event. **Acceptance Criteria:** • The system shall compare scraped content against stored content for existing regulations. • If content differs, the system shall create a regulation_changes record with old_content, new_content, previous_version, and new_version. • The change record shall be visible in the Changes & Impact view with View Diff capability. | 3 | Must Have |
| 3 | **As a** compliance officer, **I want** the system to automatically assess the impact of each regulatory change using a three-step AI pipeline (Classify → Assess → Verify), **so that** high-risk and penalty-linked changes are prioritized for immediate action. **Given** a new regulation is ingested or updated, **when** the Assessor agent processes it, **then** it performs a three-step assessment using RAG + GPT-4o-mini: classifies binding status/change type/penalty, scores impact, and self-verifies. **Acceptance Criteria:** • The assessor shall use a 3-step LLM pipeline: Step 1 Classify (free text reasoning), Step 2 Assess (JSON output), Step 3 Verify (self-check). • Impact scores shall be: Critical, High, Medium, or Low. • The system shall extract explicit compliance deadlines from regulation text (YYYY-MM-DD). • The system shall detect penalty keywords and auto-score Critical if penalty + deadline + new requirement. • Affected areas shall be selected from a 23-term standardised vocabulary. • Change type shall be classified as: New Requirement, Amended Threshold, Clarification, or Revocation. • Confidence score (0.0-1.0) shall be included; scores below 0.6 trigger automatic downgrade to Medium. • Results stored in regulation_changes with impact_score, affected_areas, explicit_deadline. | 5 | Must Have |
| 4 | **As a** compliance officer, **I want** the system to automatically generate alerts categorised by severity, **so that** the compliance team is notified of regulatory changes requiring attention. **Given** the Assessor has scored a regulation, **when** the assessment is complete, **then** an alert is created with severity level and department assignment. **Acceptance Criteria:** • Alerts shall be created for every assessed regulation change. • Severity mapping: Critical/High → Immediate Action Required, Medium → Review Recommended, Low → Informational. • Each alert shall carry the responsible department (auto-assigned from category). • Alerts shall be visible in the Alerts tab with summary cards, filters, and bulk actions. | 3 | Must Have |
| 5 | **As a** compliance officer, **I want** to manage alerts with severity filters, bulk actions, department visibility, and email digest, **so that** I can efficiently triage and communicate regulatory risks. **Given** I am on the Alerts tab, **when** I interact with alerts, **then** I can filter by severity/status, bulk mark all as read, dismiss informational alerts, view department assignments, see relative timestamps, navigate to related changes, and trigger a summary email digest. **Acceptance Criteria:** • Summary cards: Total, Unread, Immediate Action, Review, Informational. • Filter dropdowns: severity + status. • Bulk actions: Mark All Read, Dismiss Info. • Department column with auto-task status badge. • "View Change" link navigates to Changes & Impact detail. • "Send Test Alert Email" button sends formatted digest to Gmail. • Red left border on unread Immediate Action alerts. | 3 | Must Have |
| 6 | **As a** compliance officer, **I want** to investigate regulatory changes with old vs new version comparison, affected areas, and auto-task visibility, **so that** I understand exactly what changed and what actions are being taken. **Given** I am on the Changes & Impact tab, **when** I browse and filter changes, **then** I see impact summary cards, can filter by impact/areas/task status/search, view side-by-side diff, and see auto-task linkage. **Acceptance Criteria:** • 5 summary cards: Total, Critical, High, Medium, Auto-Tasks Created. • 4 filters: impact level, task status, affected areas (dynamic dropdown), text search. • Table with colour-coded left border by impact level. • Pulsing ⚠️ PENALTY badge for Critical + deadline changes. • View Diff panel: Previous Version (red border) vs Current Version (green border). • Structured diff: ➕ Added / ➖ Removed / ✏️ Modified sections. • Auto-Task column: shows status for Critical/High, "+ Create" for Medium/Low. | 5 | Must Have |
| 7 | **As a** compliance officer, **I want** the system to automatically identify compliance gaps using AI-powered cluster analysis with 5 gap types, **so that** specific areas where policies fall short are clearly identified. **Given** a regulation is ingested, **when** the Analyzer agent processes it, **then** it uses AI to select relevant policies, compares the regulation cluster against them using 3-step reasoning, and identifies gaps classified into 5 types. **Acceptance Criteria:** • The Analyzer shall use LLM to dynamically select 2-5 relevant policies (no hardcoded mapping). • Gap analysis uses 3-step reasoning: Extract requirements → Compare → Verify. • Gaps classified as: Missing Procedure, Outdated Procedure, Insufficient Detail, Missing Control, Non-Compliant Threshold. • Maximum 7 gaps per cluster analysis. • Each gap includes: description, type, severity, confidence, recommendation, source regulations. • Gaps stored in compliance_gaps table linked to reg_id and policy_id. | 5 | Must Have |
| 8 | **As a** compliance officer, **I want** to manage compliance gaps with progress tracking, type/severity filters, and task linking, **so that** I can monitor remediation progress. **Given** I am on the Gaps tab, **when** I interact with gaps, **then** I see progress bar, status cards, can filter by type/severity/status, and create linked remediation tasks. **Acceptance Criteria:** • Remediation progress bar (green/yellow/red segments). • 3 status cards: Open, In Review, Remediated. • Filter by: status, severity, gap type (5 options). • "Create Task" button opens modal pre-filled with gap info. • Creating a task auto-sets gap to "In Review". • Completing a task auto-sets linked gaps to "Remediated". | 3 | Must Have |
| 9 | **As a** compliance officer, **I want** the system to auto-generate consolidated remediation tasks for Critical/High changes grouped by category, **so that** one smart task covers multiple related regulatory changes. **Given** Critical/High alerts or gaps are created, **when** the Dispatcher agent buffers them, **then** it groups by category + department and uses LLM to generate minimum number of consolidated tasks. **Acceptance Criteria:** • Dispatcher buffers alerts for 2-5 seconds to collect related ones. • Groups by category + department (e.g., all AML/Compliance Operations together). • LLM generates tasks with verb-led titles referencing specific changes. • One task can cover multiple related regulatory changes. • Tasks linked to alerts via task_alerts and gaps via task_gaps junction tables. • Deadlines: Critical = 3 days, High = 7 days (or uses earliest regulatory deadline). • Maximum 4 tasks per cluster. | 5 | Must Have |
| 10 | **As a** compliance officer, **I want** to manage tasks with clickable linkage badges showing related gaps and changes, **so that** I can trace why each task was created. **Given** I am on the Tasks tab, **when** I view tasks, **then** each task shows clickable 🔗 gaps and 📋 changes badges that navigate to the related items. **Acceptance Criteria:** • Tasks display: title, department, deadline, status, linkage badges. • 🔗 N gaps badge → click navigates to Gaps tab filtered to those gaps. • 📋 N changes badge → click navigates to Changes & Impact filtered to those changes. • Status dropdown: Pending → In Progress → Completed. • Completing a task auto-remediates all linked gaps. • Manual task creation form available. | 3 | Must Have |
| 11 | **As a** compliance officer, **I want** to manage internal policies displayed as cards with expandable procedures, AI badge, version history, and filter by history/AI-generated, **so that** I can maintain and track policy documentation. **Given** I am on the Policies tab, **when** I view policies, **then** I see card-based layout with expandable procedures, can filter by history/AI-generated, edit with auto-versioning, and view full version trail. **Acceptance Criteria:** • Policies displayed as 2-column cards with: name, brief description, "View Procedures" toggle, Edit + History buttons. • 🤖 AI badge on policies created/updated via AI proposals. • Filter dropdown: All / Has History / No History / AI Generated. • Search by policy name. • Editing a policy auto-saves old version to policy_versions table. • History button shows full version trail with change reasons. | 3 | Must Have |
| 12 | **As a** compliance officer, **I want** the AI Advisor agent to propose policy updates with detailed procedures, **so that** I can review and accept/reject AI-drafted policies. **Given** 2+ gaps are found in the same category, **when** the Advisor agent buffers and analyzes them, **then** it proposes New Policy or Policy Update with 3-6 step procedures. **Acceptance Criteria:** • Advisor proposes only when 2+ related gaps exist. • Proposals include: policy statement + PROCEDURES section (3-6 numbered steps). • Each proposal references only top 2-3 key gaps (not all). • Proposals displayed in AI Proposals sub-tab with formatted procedures. • Accept → applies policy + saves old version + embeds in Pinecone. • Reject → discards, no changes made. • Duplicate proposals for same topic prevented. | 5 | Must Have |
| 13 | **As a** compliance officer, **I want** to upload PDF regulations that trigger the full AI pipeline, with smart version detection, **so that** I can add new regulatory documents and the system automatically identifies if it updates an existing regulation. **Given** I upload a PDF, **when** the system processes it, **then** it extracts text, checks if it's an update to an existing regulation using LLM, and stores appropriately with old/new content for View Diff. **Acceptance Criteria:** • PDF upload form with: title, category (datalist with custom input), source. • Text extraction using pdf-parse library. • Smart version detection: LLM compares against existing regulations in same category. • If update detected: creates regulation_changes row with old_content + new_content. • If new: creates new regulation and triggers full pipeline. • Emits regulation.new or regulation.updated event. • Success message indicates whether it was detected as update or new. | 5 | Must Have |
| 14 | **As a** compliance officer, **I want** to scrape a URL directly from the UI using a headless browser, **so that** I can add regulatory content from any website including JavaScript-rendered pages. **Given** I paste a URL and click Scrape, **when** the system processes it, **then** Puppeteer renders the page, extracts text, performs smart version detection, and stores the regulation. **Acceptance Criteria:** • URL scrape form with: URL, title (optional), category (datalist), source. • Puppeteer headless browser renders JS-heavy pages (e.g., MAS). • Waits for networkidle2 + 2 second delay for dynamic content. • Same smart version detection as PDF upload. • Auto-detects page title from h1/title tag if not provided. • Rejects pages with < 50 chars of extractable content. | 3 | Must Have |
| 15 | **As a** compliance officer, **I want** to view a Regulations Knowledge Base with filters, detail panel, and related items, **so that** I have a centralized searchable repository of all regulatory information. **Given** I am on the Regulations tab, **when** I browse regulations, **then** I can filter by category/source/status, click titles to open official sources, view detail panel with full content + related changes + gaps. **Acceptance Criteria:** • Filters: category, source, assessment status (assessed/pending), text search. • Clickable titles → open official source URL in new tab. • "View Details" → detail panel with: content, metadata, related impact changes, related gaps. • Count badge showing total regulations. • Export Knowledge Base as CSV. | 3 | Must Have |
| 16 | **As a** compliance officer, **I want** to view reports focused on regulatory changes, gap analysis, task progress, and compliance posture, **so that** I can prepare management reports and track overall compliance health. **Given** I am on the Reports tab, **when** I navigate between 4 sub-tabs, **then** I see focused analytics with KPI cards and charts. **Acceptance Criteria:** • Tab 1 — Regulatory Changes: KPI cards (total, critical/high, penalty-linked), impact doughnut, category bar, timeline. • Tab 2 — Gap Analysis: KPI cards (open, in review, remediated, resolution rate), gap type pie, gaps by policy, status bar. • Tab 3 — Tasks & Remediation: KPI cards (total, pending, in progress, completed), task status pie, department bar, deadline burndown. • Tab 4 — Compliance Posture: overall compliance score %, regulations monitored, policies count, policy coverage heatmap (colour-coded by gap count). • Print Report button generates formatted printable report. | 5 | Must Have |
| 17 | **As a** compliance officer, **I want** to view a comprehensive audit trail with summary cards, agent activity breakdown, timeline view, and response chain, **so that** I have full evidence for regulatory inspections. **Given** I am on the Audit Trail tab, **when** I interact with it, **then** I see 4 summary cards, agent breakdown, 3 view modes, AI/human filter, and printable audit report. **Acceptance Criteria:** • Summary cards: Total Actions, This Week, 🤖 AI Agent Actions, 👤 Human Actions. • Agent Activity Breakdown: Scraper, Assessor, Analyzer, Dispatcher, Advisor counts. • 3 view modes: Table View, Timeline View, Response Chain View. • AI vs Human filter dropdown. • Response Chain: select regulation → see full chain (Scraped → Assessed → Gaps → Tasks → Status). • Print Audit Report generates formatted document. • Expandable detail rows for LLM action logs. | 5 | Must Have |
| 18 | **As a** compliance officer, **I want** to receive ONE consolidated email digest summarizing all Critical/High alerts, triggered manually, **so that** I can communicate regulatory risks to stakeholders efficiently. **Given** alerts have been buffered by the Notifier agent, **when** I press "Send Test Alert Email", **then** one formatted digest email is sent to my Gmail with all Critical/High alerts in a table. **Acceptance Criteria:** • Notifier agent buffers all Critical/High alerts (never sends automatically). • Email sent only when user presses the button. • Digest contains: Critical/High counts, table with regulation, department, deadline, summary. • Email formatted with styled HTML (dark header, KPI cards, "Open Dashboard" button). • Uses Gmail SMTP with App Password authentication. | 3 | Must Have |
| 19 | **As a** compliance officer, **I want** to securely log in and see a home page before entering the dashboard, **so that** I have a clear entry point with quick stats. **Given** I open the app, **when** I enter credentials, **then** I see a home page with GLDB branding, quick stats (alerts, open gaps, pending tasks), and a "Go to Dashboard" button. Clicking the GLDB logo returns to home. **Acceptance Criteria:** • Login overlay with email/password + bcrypt validation. • Home page after login: GLDB logo, system description, 3 stat cards, "Go to Dashboard" button. • Sidebar hidden on home page, appears on dashboard entry. • Clicking GLDB logo in navbar returns to home page. • Logout returns to login overlay. | 2 | Must Have |
| 20 | **As a** compliance officer, **I want** a collapsible sidebar, dark mode, consistent table styling, and responsive UI, **so that** I can customise my workspace. **Given** I am using the dashboard, **when** I interact with UI controls, **then** I can toggle sidebar (full-width content), toggle dark mode (saved preference), and see consistent table styling across all tabs. **Acceptance Criteria:** • "☰ Menu" button toggles sidebar visibility. • Dark mode toggle with localStorage persistence. • All tables: dark header, 0.9rem font, consistent padding, subtle hover, uppercase headers. • Sticky sidebar that doesn't scroll with content. • Pagination on all tables (10 items per page). | 2 | Should Have |
| 21 | **As a** compliance officer, **I want** to manage regulatory sources, **so that** the system tracks which authorities are being monitored. **Given** I am on the Sources tab, **when** I add/edit/delete sources, **then** the system updates the regulatory_sources table. **Acceptance Criteria:** • Display: Source Name, Base URL, Created Date, Actions. • Add/Edit/Delete functionality. • Sources available in regulation upload dropdowns. | 2 | Should Have |
